# Utility plugin feature and accuracy audit

Date: 2026-09-27. Read-only source audit; no new tests, builds, or DSP measurements were run for this report. MIDI and IAMF excluded. TokenSave was consulted first; the main index was rebuilding and the math-audio sibling index was 87 minutes old, so findings use current file reads rather than graph freshness. Paths below are relative to `/home/pierre/src/all_of_sotf/sotf-daw/crates/sotf-plugins/crates/` unless stated otherwise.

## Ranked findings

### 1. StereoImager: band-width subtraction does not implement the advertised band attenuation

**Verified algebraic defect; rendered regression still needed.** `sotf-plugin-stereo-imager/src/lib/stereo_imager_plugin.rs:487` combines the unfiltered side with corrections made from phase-rotated LR4 bands:

`Sout = global * [S + (low*enable-1) LP1(S) + (mid-1) LP2(HP1(S)) + (high-1) HP2(HP1(S))]`.

With neutral widths and Mono Bass enabled this becomes `Sout=(1-LP1)S`. For the standard LR4 implemented by math-audio, `LP1(fc)=-0.5`, so the side amplitude is **1.5 (+3.52 dB)** at the bass crossover. It can also increase side energy below the crossover. This conflicts with the control's declared bass-collapse behavior (`src/params.rs:100`). Setting all three band widths to zero likewise leaves `S-(LP1+HP1*(LP2+HP2))S`, generally nonzero because the sum has allpass phase. The successful global-width-zero case does not establish per-band-zero behavior.

Source confirmation: `sotf-host/src/lib.rs:59` reexports the LR4 implementation; `/home/pierre/src/all_of_sotf/math-audio/crates/math-iir-fir/src/lr4_crossover.rs:65` cascades two Butterworth stages on each branch. Linkwitz's own [crossover derivation](https://www.linkwitzlab.com/crossovers.htm) distinguishes unit-magnitude allpass summation from identity and gives the LR4 lowpass polynomial. The numerical 1.5 result is derived from that transfer function and current code, not a measured run.

**Tests missing the defect:** `sotf-plugin-stereo-imager/tests/integration.rs:329` and `src/lib/tests.rs:325` test Mono Bass using DC. At DC LP=1, so the erroneous subtraction happens to work. `integration.rs:258` tests global width zero, not all band widths zero. Neutral sample transparency tests are valid but do not constrain nonneutral band response.

**Next evidence:** anti-phase coherent tones below, at, and above each crossover; independently derive the intended side transfer and assert mono-bass attenuation and all-band-zero collapse while retaining neutral transparency. Requires choosing complementary bands or phase-aligned reference topology, not adjusting tolerances.

### 2. MonoToStereo: hostile final sample poisons state when leaving duplicate fast path

**Verified control-flow defect; execution regression still needed.** In `sotf-plugin-mono-to-stereo/src/lib/mono_to_stereo_plugin.rs:403`, width=0/no-Haas processing replaces non-finite samples with zero in the output. However line411 stores the **raw** final input in `last_input`. When width subsequently becomes nonzero, line422 calls `prime_decorrelator(last_input)`; line270 writes that value into all allpass histories. A NaN or infinity at the previous block's last frame therefore poisons the right channel even when all later input is finite.

**Existing test limitation:** `src/lib/tests.rs:1027`, named `non_finite_input_is_silenced_and_never_poisons_state`, injects at frames4/111/512 of1024 and keeps width fixed. It never injects at the final frame or crosses from duplicate processing into the decorrelator. The title overstates the tested transition coverage.

**Next evidence:** width0/Haas0, one block ending in each of NaN/+Inf/-Inf, then enable width and render finite input using several callback partitions. Compare with replacing the hostile sample by zero before processing, and assert finite state/output.

### 3. ABCompare: loudness correction updates at callback boundaries, with no quantitative matching oracle

**Verified scheduling behavior; numerical/audibility impact not measured.** `sotf-plugin-ab-compare/src/lib/abcompare_plugin.rs:1093` ingests the complete callback, then refreshes loudness if the callback crossed a50ms diagnostic boundary. `advance_diagnostic_scheduler` atline540 returns one boolean and retains only the modulo remainder. `sotf-host/src/auto_gain.rs:246` changes the gain target during that refresh. The subsequent sample loop (`abcompare_plugin.rs:1136`) applies that new target to the **entire callback whose end supplied the measurement**. Different callback partitions therefore refresh at different audio instants and apply different target histories; callbacks spanning multiple50ms boundaries collapse them into one refresh. This is more than UI-throttle timing because it controls audio gain.

**Existing test limitation:** `src/tests/misc.rs:126` and167 only check that a+6dB/-6dB branch receives correction with the appropriate sign after repeated100ms callbacks. They do not require correction magnitude near6dB, output level equivalence, or partition independence. The strong bypass/latency tests in `src/tests/latency_passthrough.rs` generally disable auto gain and do not cover this path.

**Next evidence:** independently measured output gain/LUFS difference after settling for known±6dB paths, then an identical level-change timeline rendered with64-,256-,4096-frame and irregular callbacks. Separate steady-state accuracy from transient scheduling; choose a sample-clock measurement cadence if exact audio invariance is intended.

## Scope and interpretation

These are focused utilities, not products requiring every competing feature. Tempo sync, random blind A/B trials, more crossover modes, individualized HRTFs and similar extensions are not classified as bugs without a repository promise. Strong existing tests are credited above; passing test names or finite output alone are not treated as accuracy evidence. The highest-priority next work is to reproduce the two source-proven defects and quantify ABCompare's gain timeline, without weakening existing tolerances.

## Follow-up implementation and numerical evidence (AUD-025 / AUD-026)

The read-only findings above were followed by an authorized, limited fix in StereoImager and MonoToStereo.

- **StereoImager reproduction:** an antiphase 250 Hz tone with Mono Bass enabled measured side gain **1.500004937** at 32 kHz, confirming the predicted +3.52 dB error. All three band widths at zero left a nonzero side sample of ±0.108801395 instead of the independently calculated mid. Both regressions failed before the implementation change (`/tmp/sotf-stereo-imager-repro.log`).
- **StereoImager correction:** parallel first-order lowpasses form the complementary side bands `L`, `U−L`, and `S−U`. Their algebraic sum is the original side; the mid remains untouched. Mono Bass becomes `S−L`. First-order complementary low/high sums have the identity reconstruction property described in [Linkwitz's primary crossover analysis](https://www.linkwitzlab.com/crossovers.htm); LR4 low/high sums instead carry phase rotation. This deliberately chooses **6 dB/octave** slopes to preserve zero latency and neutral sample transparency. Steeper phase-aligned or linear-phase modes remain an unimplemented feature, and no LR24/SOTA isolation claim is made. Frequency control indices and smoothing remain unchanged; updates at or above the active sample rate's Nyquist are now rejected before any state changes.
- **Independent response oracle:** `sotf-plugin-stereo-imager/tests/crossover_response.rs` derives complex response from the analog prototype `H(s)=1/(1+s/wc)` and the prewarped bilinear transform, independently of production recurrence/coefficients. It measures **147 combinations** (7 control configurations × 7 frequencies from 20 Hz to 12 kHz × 32/48/96 kHz), using streamed irregular callbacks and coherent tone projection after a 0.5 s settling period. Every complex response error is below **2×10⁻⁶ absolute gain**. Additional checks cover all-band-zero collapse from the first sample, mid/side orthogonality, bit-identical callback partitioning during cutoff/width/mix automation, reset midway through a frequency ramp versus fresh target configuration, and cold/reset/automated processing without allocation.
- **MonoToStereo reproduction/correction:** when a duplicate-path block ended in NaN or either infinity, subsequent width automation primed allpass state with that invalid cached sample and generated non-finite output (`/tmp/sotf-mono-to-stereo-repro.log`). The final cached sample now uses the same finite-or-zero sanitation as the rendered duplicate output. Tests compare against explicitly sanitized input before/after reset, verify exact callback-partition invariance through width automation, and check allocation-free cold processing, first decorated callback, and reset.
- **Verification:** `cargo test -p sotf-plugin-stereo-imager -p sotf-plugin-mono-to-stereo` passes **114 tests, zero ignored** (`/tmp/sotf-stereo-mono-tests.log`). Focused Clippy with warnings denied and final diff checks accompany the implementation checkpoint.

## Follow-up ABCompare sample-clock correction (AUD-032)

- **Reproduction:** the same 44.1 kHz signal through a −6 dB B path produced a maximum output difference of **0.0008531213** between 64-frame and 4096-frame callbacks. A one-second callback also changed samples in its initial measurement window using statistics from later audio. Both regressions failed before production edits (`/tmp/sotf-abcompare-repro.log`); the independent settled inverse-gain magnitude test already passed, isolating the scheduling defect from steady-state level accuracy.
- **Correction:** ABCompare meters and mixes segments ending at fixed `floor(sample_rate / 20)`-frame boundaries. Each segment renders using the previously known gain target, then updates the target and diagnostics for following samples. Every boundary is retained in a large callback. The original nested path callbacks, parameter indices/defaults, limiter range, and latency contract remain unchanged. Empty-path and normal processing use the same measurement clock, which starts at zero after initialization/reset.
- **Warmup:** the existing loudness implementation completes its first energy block after approximately 100 ms, then averages available history until its full 400 ms momentary or 3 s short-term window is populated. Gain smoothing adds adaptation time; none of this adds audio latency. This behavior is now documented in the crate README.
- **Evidence:** new `tests/loudness_timing.rs` checks analytically expected inverse correction for ±6 dB paths in both loudness modes (<0.02 dB settled output mismatch), callback partition agreement (<10⁻⁶ absolute sample error across 64/4096/9600/irregular callbacks at 44.1/48 kHz), causal initial-window gain, reset versus fresh-instance exact output, and zero allocations during cold/established/post-reset callbacks crossing twenty measurement boundaries. The full crate suite passes **113 tests, zero ignored** (`/tmp/sotf-abcompare-tests.log`), with Clippy `--lib --tests -- -D warnings` passing (`/tmp/sotf-abcompare-clippy.log`) and a clean scoped diff check.

## Mute/solo JSON default alignment (AUD-048)

The runtime JSON struct used serde's false default for omitted `enabled`, while
the shared schema and native wrappers declared true. It now obtains the default
from that schema. An omitted enabled value applies configured mute/solo states;
an explicit `enabled: false` still bypasses them. Existing configurations that
relied on an omitted enabled field to disable nondefault channel states should
store false explicitly. Empty channel state configurations remain transparent.

The new regression failed before correction and checks both parameter defaults
and actual muted audio. All 45 unit and 21 integration tests pass; the bridge
and FFI suites also pass with the aligned default.
