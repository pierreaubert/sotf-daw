# Remaining estimator problem

The new independent noise-step guard exposes a failure that the gentle stationary-noise guard cannot see: natural DD clean-power prediction passes substantially more nonstationary noise even before the SNR-dependent gain change. State independence is a useful mathematical invariant, but it does not establish correct source/noise attribution.

The current `mcra.rs` header calls its estimator IMCRA, while its executable update is a single per-bin minimum indicator, time smoothing and probability-controlled noise averaging. Cohen's 2003 description includes frequency/time smoothing, two smoothing/minimum-tracking stages, Gaussian-model probability estimation and bias handling. This identifies an implementation/model gap worth investigating; it does not prove that a full paper implementation fixes this dataset. See the [author's paper](https://www.ee.technion.ac.il/Sites/People/IsraelCohen/Publications/SAP_Sep2003.pdf), DOI 10.1109/TSA.2003.811544, and [author software page](https://israelcohen.com/software/).

The author-hosted software link from the legacy publication list points to `https://webee.technion.ac.il/Sites/People/IsraelCohen/Download/omlsa.m`; two web attempts timed out. No local PDF was downloaded or read: the configured Headroom MarkItDown executable is absent, so research used the already converted search excerpt and author HTML. No third-party mirror code was used as an authority or copied into the crate.

A further limitation is relevant: the author's 2012 transient-interference paper notes that abrupt interference may be classified as speech by IMCRA. Therefore upgrading noise estimation requires an explicit transient/noise model and the preserved noise-only counterexample, not merely an IMCRA name or a probability-like variable. See the [author's 2012 paper](https://webee.technion.ac.il/Sites/People/IsraelCohen/Publications/TASLP_Nov2012.pdf).

Any next production hypothesis must declare its source/noise assumptions independently, retain the original two vowel/36 SDR/settled noise guards and the new 12 nonstationary-noise/control windows, preserve supplied-profile authority, and reject rather than tune on failure. Held-out multilingual/noise/listening data and native hosts remain open external requirements. The failed gain/feedback variants do not justify changing existing parameter semantics or weakening a guard.
